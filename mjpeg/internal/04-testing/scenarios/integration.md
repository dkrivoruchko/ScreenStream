# Integration inspections and real adapter smoke

Behavior: [maintained contract](../../01-lifecycle/streaming-host.md). Source inspection verifies declarations; supplied test graphs verify only their installed boundaries. Resolving the actual Koin graph is a separate integration check. Actual projection, foreground and Android networking require L2.

## Bounded configuration inspection

<a id="mjpeg-cfg-01"></a>

- **Inert module metadata and declared component.** Current module Kotlin and matching resources/manifest are inspected. Check bounded metadata and Service declaration. Id MJPEG, priority 40, localized metadata resources and MjpegStreamingModuleService are wired; metadata singleton does not construct controller/capture/listener resources. Service is not exported and declares mediaProjection foreground type.

<a id="mjpeg-cfg-02"></a>

- **Koin binding and inert controller installation.** Inspect ComponentScan/module annotations and factory/singleton bindings. MJPEG binds StreamingModule and registers HttpDelivery/NetworkAddressMonitor factories. Install the real controller with its exact runtime/Service in a supplied test graph without starting streaming resources. Verify actual module graph resolution separately; shared manager installation internals remain outside scope.

<a id="mjpeg-cfg-03"></a>

- **Manifest and runtime dependency configuration.** Current Kotlin integration depends on LAN/network/foreground access and actual patched CIO graph. Inspect MJPEG manifest, module/root build and version catalogue. Manifest declares INTERNET, ACCESS_LOCAL_NETWORK, ACCESS_NETWORK_STATE, foreground and media-projection foreground permissions; actual SDK/toolchain/runtime versions and patched network substitution are recorded. Inspection does not prove merged APK or device behavior.

The actual app integration provides `LocalRuntimePermissions` from the Activity root independently of module composition. Inspect the enum aliases, root slot/history and native direct UI admission together: the native address button submits manual admission, the app owns an accepted explanation/system/Settings visit, and the controller independently reads the OS for listener readiness. A supplied controller graph or non-UI permission-plan fixture does not establish this UI lifetime boundary.

## Packaged assets and real lifetime smoke

<a id="mjpeg-cfg-04"></a>

Keep host asset/Service/controller checks separate from actual-graph/platform smoke. On a packaged Android artifact, activate MJPEG, read root/placeholder, obtain consent, start capture, then Stop and shut down the module. The tested foreground/capture/media boundary should produce a recognizable JPEG and cleanly stop. Browser UI, all transforms/ABIs and shared-core internals remain outside this smoke.

Reopen a fresh lifetime using saved preferences. PIN policy governs preparation; the new runtime starts without prior capture, selected capture image, peer blocks, counters or endpoint history. Old owners cannot authorize successor work. Check applied current authority, not random PIN/token inequality.

Apply this outcome across the supported API 24–37 range, recording actual runtime, target, grants and device/build for L2 evidence. Distinct platform prerequisites include notification channels/background launch on 26+, foreground permission on 28+, projection service type on 29+, background FGS admission on 31+, notification permission/visibility on 33+, and per-session projection consent plus type permission on 34+. Notification denial does not itself prohibit starting a foreground service. Android 15 QPR1 and later can end projection on screen lock or user chip Stop; QPR/build is material, not just API 35. API 36 adds public tether metadata; API 37/target 37 requires LAN grant and an external client for incoming reachability. Android 16's optional local-network compatibility restriction needs separate recorded configuration.

Downstream Engine behavior also varies by SDK, but its implementation remains engine-owned. An MJPEG smoke establishes only the observed capture boundary on its recorded platform. Pure saved/wire/value histories inherit [the common supported-range contract](../testing.md#supported-android-versions) without an every-SDK execution claim.

[Foreground prerequisites](https://developer.android.com/develop/background-work/services/fgs/launch), [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [projection consent](https://developer.android.com/about/versions/14/behavior-changes-14#user-consent-required), [Android 15 QPR1 projection changes](https://developer.android.com/about/versions/15/behavior-changes-all) and [local-network enforcement](https://developer.android.com/privacy-and-security/local-network-permission) define these platform limits.

For ordinary-permission UI qualification, keep presentation state, `tryRequest` admission and actual OS grant separate. Attempt admission while paused and while another permission occupies the slot; false must not be treated as queued work. With notifications ungranted and the slot free, LAN/audio admission must not be rejected for notification denial. Admit and cancel a LAN explanation, retry manually, confirm Settings and return, rotate during a launched system dialog, then leave the originating screen. The accepted app-owned UI remains until its own dismissal/result/return; no module waiter owns it. Audio aliases share their underlying grant and the same lazily created flow; Requesting represents the current pending permission rather than a grant. A previously observed flow may retain a cached hint after an unrelated OS change: resume handles the current request rather than scanning all permissions. Check that consumers use fresh `isGranted` before protected actions and that the native button's fresh check takes precedence over cached presentation state. Verify that native MJPEG does not request LAN permission on screen entry, filter changes, notification grant or resume; only the address-row action attempts admission. Other modules' automatic policies are separate. Fresh controller grant checks update only eligible current listeners without starting capture. These are boundary requirements, not a claim that the MJPEG non-UI suite exercises the shared host.

Qualify notification education separately: every fresh non-restored root offers it once if notification access is unavailable, including app-wide notification disablement; saved pending/null state survives rotation or restored process state. Dismiss it with Not now, Back and outside interaction, return from background/Settings, and verify that those transitions do not create another offer. Verify availability as app-wide enabled plus the applicable runtime grant, including API 24–32 where disabled notifications route directly to Settings. Check Continue/native request versus Open settings for notification availability and observed-rationale history, not callback membership. For each ordinary permission, record evidence only when its runtime permission is required, the fresh grant is denied and true rationale is observed: before native launch, or after a false callback entry followed by the fresh check. Cancellation may supply a nonempty false result, and a grant callback need not represent a new user choice; neither creates rationale history by itself. Valid earlier evidence survives a later false rationale. After successful persistence, a fresh root loads the generic `AppSettings.permissionsWithObservedRationale` set; restored root state preserves its saveable list. Verify notification, LAN and shared audio permission names, and remove each name from the root list and saved set after an applicable runtime grant is observed through the host's checks. This removal depends on the runtime grant even when app-wide notification delivery remains disabled; unrelated grant changes are not globally monitored. Keep this durable evidence separate from the pending permission and phase, which belong to root UI state rather than AppSettings. Include a first-seen existing-denial case with no evidence: Requestable is possible, the exact prior decision is unknown, and Settings → Device notification settings remains available for recovery. These are app-host qualification requirements, not MJPEG test-coverage claims.
